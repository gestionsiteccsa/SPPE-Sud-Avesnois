# Baseline Deployment Django — 2026-08-15

## Django deployment

Django précise que `runserver` n’est pas destiné à la production et fournit une checklist de déploiement.

Références :
https://docs.djangoproject.com/en/6.0/howto/deployment/
https://docs.djangoproject.com/en/6.0/howto/deployment/checklist/

## WSGI / ASGI

Django supporte WSGI et ASGI pour le déploiement.

Références :
https://docs.djangoproject.com/en/6.0/howto/deployment/wsgi/
https://docs.djangoproject.com/en/6.0/howto/deployment/asgi/

## Static

Le déploiement des fichiers statiques passe notamment par `collectstatic` et une stratégie de service adaptée.

Référence :
https://docs.djangoproject.com/en/6.0/howto/static-files/deployment/

## HTTPS / sécurité

La checklist Django couvre notamment :
- DEBUG ;
- SECRET_KEY ;
- ALLOWED_HOSTS ;
- HTTPS ;
- cookies ;
- settings de sécurité.

Référence :
https://docs.djangoproject.com/en/6.0/howto/deployment/checklist/

## Docker

Docker recommande notamment les multi-stage builds et l’usage d’un utilisateur non privilégié dans ses bonnes pratiques de Dockerfile.

Référence :
https://docs.docker.com/build/building/best-practices/

## Philosophie retenue

- Docker optionnel ;
- déploiement classique pleinement supporté ;
- staging proche de production ;
- aucune release sans health check ;
- rollback documenté ;
- migrations sensibles relues ;
- secrets hors Git.
