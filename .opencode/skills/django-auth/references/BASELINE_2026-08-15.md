# Baseline Django Auth — 2026-08-15

Vérifier la documentation de la version Django réellement utilisée.

## Système d’authentification

Django fournit un système complet comprenant notamment :

- utilisateurs ;
- mots de passe ;
- groupes ;
- permissions ;
- sessions ;
- vues/formulaires d’authentification.

Référence :
https://docs.djangoproject.com/en/6.0/topics/auth/

## Custom user model

La documentation officielle précise que changer `AUTH_USER_MODEL` après création de tables est possible mais complexe, notamment à cause des dépendances et migrations.

Référence :
https://docs.djangoproject.com/en/6.0/topics/auth/customizing/

## Auth standard

Django fournit des vues/formulaires pour :

- login ;
- logout ;
- password change ;
- password reset.

Référence :
https://docs.djangoproject.com/en/6.0/topics/auth/default/

## Mots de passe

Django fournit :

- hashers ;
- validation ;
- upgrade des hashes ;
- API `set_password()` / `check_password()`.

Référence :
https://docs.djangoproject.com/en/6.0/topics/auth/passwords/

## Sessions

Django fournit un framework de sessions intégré.

Référence :
https://docs.djangoproject.com/en/6.0/topics/http/sessions/

## Philosophie retenue

- utiliser le système natif autant que possible ;
- customiser tôt seulement les décisions structurantes ;
- ne jamais gérer le hash soi-même ;
- permissions objet explicitement vérifiées ;
- récupération de compte traitée comme surface sensible.
