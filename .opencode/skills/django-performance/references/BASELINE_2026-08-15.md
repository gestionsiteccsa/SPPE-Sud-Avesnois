# Baseline Django Performance — 2026-08-15

Vérifier la documentation de la version Django réellement utilisée.

## Optimisation DB

La documentation officielle Django recommande explicitement de :

- profiler avant d’optimiser ;
- comprendre `select_related()` et `prefetch_related()` ;
- utiliser les opérations DB plutôt que Python lorsque pertinent ;
- récupérer uniquement les données nécessaires ;
- utiliser `QuerySet.explain()` pour comprendre l’exécution.

Référence :
https://docs.djangoproject.com/en/6.0/topics/db/optimization/

## QuerySets

`prefetch_related()` exécute des requêtes additionnelles après la requête principale et assemble les relations en Python.

`select_related()` utilise des jointures SQL pour les relations adaptées.

Référence :
https://docs.djangoproject.com/en/6.0/ref/models/querysets/

## Cache

Django propose :

- per-site cache ;
- per-view cache ;
- template fragment cache ;
- low-level cache API.

Référence :
https://docs.djangoproject.com/en/6.0/topics/cache/

## Pagination

Django fournit `Paginator` pour découper les jeux de données.

Référence :
https://docs.djangoproject.com/en/6.0/topics/pagination/

## Philosophie retenue

- mesurer ;
- corriger d’abord ORM/volume/schema ;
- cache ensuite ;
- éviter les N+1 ;
- éviter les listes non bornées ;
- ne pas introduire une infrastructure supplémentaire sans besoin réel.
