# Baseline Django Security — 2026-08-15

Ce fichier documente les références de conception. Vérifier la documentation correspondant à la version Django réellement utilisée.

## Django Security

La documentation Django officielle couvre notamment :

- protection XSS via auto-escaping des templates ;
- protection CSRF ;
- protection SQL injection via ORM paramétré ;
- protection clickjacking ;
- Host header validation via ALLOWED_HOSTS ;
- HTTPS ;
- sécurité des fichiers uploadés ;
- SecurityMiddleware.

Source de référence :
https://docs.djangoproject.com/en/6.0/topics/security/

## CSRF

Django recommande que les méthodes HTTP sûres soient sans effet de bord, et protège les méthodes non sûres via le mécanisme CSRF.

Source :
https://docs.djangoproject.com/en/6.0/ref/csrf/

## OWASP Django Security Cheat Sheet

OWASP fournit des recommandations complémentaires spécifiques Django :

## File Upload

OWASP recommande notamment :

- allowlist extensions ;
- validation du type ;
- renommage ;
- limites de taille ;
- stockage approprié ;
- protection contre fichiers malveillants.

Source :
https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html

## SSRF

Toute URL contrôlée par l’utilisateur et récupérée par le serveur doit être considérée sensible.

Source :
https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html

## SQL Injection

L’usage de requêtes paramétrées est fondamental.

Source :
https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html

## Revue sécurité

OWASP recommande une revue dédiée pour chercher notamment injections, XSS, path traversal et uploads dangereux.

Source :
https://cheatsheetseries.owasp.org/cheatsheets/Secure_Code_Review_Cheat_Sheet.html
