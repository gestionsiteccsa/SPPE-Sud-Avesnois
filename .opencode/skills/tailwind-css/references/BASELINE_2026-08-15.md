# Baseline Tailwind CSS — 2026-08-15

Toujours vérifier la version réellement installée avant de suivre une syntaxe.

## Tailwind CSS

Tailwind se décrit comme un framework CSS utility-first.

Référence :
https://tailwindcss.com/

## Tailwind CLI

La documentation actuelle propose Tailwind CLI comme méthode simple d’installation et indique également qu’un exécutable standalone existe pour un usage sans installation Node.js.

Référence :
https://tailwindcss.com/docs/installation/tailwind-cli

## Détection des classes

Tailwind scanne les fichiers source et génère le CSS correspondant aux classes détectées.

Référence :
https://tailwindcss.com/docs/detecting-classes-in-source-files

Conséquence :
éviter de construire dynamiquement des fragments de noms de classes qui n’apparaissent jamais sous forme complète dans le code source.

## Theme variables

Tailwind v4 utilise notamment `@theme` et des variables CSS pour définir les tokens qui pilotent les utilities.

Référence :
https://tailwindcss.com/docs/theme

## Responsive

Les utilities peuvent être appliquées par breakpoint via les variants responsive.

Référence :
https://tailwindcss.com/docs/responsive-design

## Dark mode

Tailwind fournit le variant `dark:` et permet une personnalisation de la stratégie de détection du thème.

Référence :
https://tailwindcss.com/docs/dark-mode

## Custom styles

Tailwind permet de sortir des contraintes du thème et d’ajouter du CSS custom lorsque nécessaire.

Référence :
https://tailwindcss.com/docs/adding-custom-styles

## Philosophie retenue

- respecter la version installée ;
- Tailwind v4 n’est pas traité comme Tailwind v3 ;
- source scanning compris et testé ;
- utilities d’abord ;
- composants Django pour la réutilisation ;
- arbitrary values avec modération ;
- accessibility et responsive obligatoires ;
- aucun framework build supplémentaire sans besoin.
