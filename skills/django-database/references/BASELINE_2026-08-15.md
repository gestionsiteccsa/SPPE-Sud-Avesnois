# Baseline Django Database — 2026-08-15

Vérifier la documentation officielle de la version Django réellement utilisée avant toute décision dépendante de version.

## Contraintes

Django fournit notamment `CheckConstraint` et `UniqueConstraint` pour déclarer des contraintes base de données.

Les contraintes peuvent participer à la validation des modèles, mais la contrainte DB reste importante pour garantir l’intégrité en concurrence.

## Transactions

Django fournit `transaction.atomic()` pour définir une unité atomique de requêtes.

Les transactions doivent rester aussi courtes que possible.

## Migrations

Les migrations sont versionnées par app mais leurs dépendances peuvent traverser les apps.

PostgreSQL et SQLite prennent en charge les transactions DDL utilisées par les migrations Django dans de nombreux cas.

## PostgreSQL

Django propose des opérations spécifiques PostgreSQL, notamment la création d’index concurrents et des stratégies d’ajout/validation progressive de certaines contraintes.

Ces mécanismes sont particulièrement utiles pour réduire les impacts sur des tables volumineuses, mais nécessitent une maîtrise des migrations atomiques/non atomiques.

## F expressions

Les `F()` expressions permettent de déléguer des opérations au moteur de base de données sans charger puis réécrire la valeur côté Python.

Elles sont utiles notamment pour certains incréments concurrents.

## SQL brut

`RunSQL` existe pour les opérations non prises en charge directement par Django. Il doit rester explicite, paramétré et réversible lorsque possible.
