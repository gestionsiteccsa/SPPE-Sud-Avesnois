# Baseline Backup & Restore — 2026-08-15

## PostgreSQL

La documentation PostgreSQL décrit trois grandes familles de sauvegarde :

- SQL dump ;
- sauvegarde au niveau système de fichiers ;
- archivage continu.

Référence :
https://www.postgresql.org/docs/current/backup.html

## pg_dump

`pg_dump` sauvegarde une base PostgreSQL. Les formats archive `custom` (`-Fc`) et `directory` (`-Fd`) permettent un usage flexible avec `pg_restore`.

Références :
https://www.postgresql.org/docs/current/app-pgdump.html
https://www.postgresql.org/docs/current/backup-dump.html

## pg_restore

`pg_restore` restaure une archive créée par `pg_dump` dans les formats non plain-text.

Référence :
https://www.postgresql.org/docs/current/app-pgrestore.html

## PITR

PostgreSQL supporte l’archivage continu et la restauration à un instant donné.

Référence :
https://www.postgresql.org/docs/current/continuous-archiving.html

## Django

La checklist de déploiement Django recommande explicitement d’avoir une stratégie de backup pour la base de données.

Référence :
https://docs.djangoproject.com/en/6.0/howto/deployment/checklist/

## OWASP

OWASP recommande :
- sauvegardes régulières ;
- permissions adaptées ;
- chiffrement lorsque pertinent ;
- tests réguliers des procédures de restauration.

Références :
https://cheatsheetseries.owasp.org/cheatsheets/Database_Security_Cheat_Sheet.html
https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html
https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html
