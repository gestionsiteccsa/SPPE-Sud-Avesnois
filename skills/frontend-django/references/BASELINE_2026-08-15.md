# Baseline Frontend Django — 2026-08-15

Vérifier la documentation correspondant à la version Django réellement utilisée.

## Templates

Django définit les templates comme la partie statique de la sortie HTML accompagnée de syntaxe permettant d’insérer les données dynamiques.

Référence :
https://docs.djangoproject.com/en/6.0/topics/templates/

## Forms

Django fournit un système complet pour :
- construire des formulaires ;
- valider des données ;
- afficher les erreurs ;
- produire les widgets HTML.

Références :
https://docs.djangoproject.com/en/6.0/topics/forms/
https://docs.djangoproject.com/en/6.0/ref/forms/

## ModelForms

Les ModelForms simplifient les formulaires correspondant directement aux modèles.

Référence :
https://docs.djangoproject.com/en/6.0/topics/forms/modelforms/

## Static files

`django.contrib.staticfiles` gère CSS, JavaScript et images statiques.

Référence :
https://docs.djangoproject.com/en/6.0/howto/static-files/

En production, Django documente un workflow où `collectstatic` collecte les fichiers puis une couche adaptée les sert.

Référence :
https://docs.djangoproject.com/en/6.0/howto/static-files/deployment/

## Uploads

Les fichiers utilisateurs sont différents des static files et nécessitent une gestion dédiée.

Référence :
https://docs.djangoproject.com/en/6.0/topics/http/file-uploads/

## Accessibilité

WCAG 2.2 insiste notamment sur :
- labels/instructions ;
- structure ;
- interaction clavier ;
- noms accessibles.

Références :
https://www.w3.org/WAI/WCAG22/quickref/
https://www.w3.org/WAI/ARIA/apg/

## Philosophie retenue

- HTML natif d’abord ;
- progressive enhancement ;
- Django Forms côté serveur ;
- JS seulement lorsqu’il apporte une valeur ;
- accessibilité intégrée à la feature ;
- static ≠ media ;
- frontend jamais utilisé comme barrière de sécurité.
